## What the agent builds

# M2 — Algorithm Phases

## Objective
Implement the three phases of the Leiden algorithm that operate on CompactNetwork and Clustering from M1.

## The three phases

### Phase 1: Local Move
Greedy quality improvement via circular queue. Each node temporarily leaves its cluster, tries all neighboring clusters, moves to the best quality gain. Neighbors of moved nodes are re-queued.

### Phase 2: Refinement (the Leiden innovation over Louvain)
Within each Phase 1 community, restart from singleton partition and stochastically merge sub-clusters. The `randomness` parameter controls stochasticity. This phase guarantees well-connected communities — Louvain has no equivalent.

### Phase 3: Aggregation
Contract refined clusters into super-nodes. Build a new CompactNetwork over super-nodes. Recurse `improveClustering` on the induced network. Continue until no improvement.

## Quality Value Increment formula (graspologic-native version)
```
QVI = edgeWeightToCluster - (nodeWeight × clusterWeight × adjustedResolution)
```
This is the formula from graspologic-native, which corrects a bug in the CWTSLeiden Java reference. Use this version — document the deviation.

  <algorithm>
    <phase1 name="local-move">
      Process nodes in random shuffled order (circular queue).
      For each node: remove from current cluster, try all neighboring clusters,
      move to best quality improvement. Re-queue changed neighbors.
      Repeat until queue empty. Returns bool (any improvement).

      Quality Value Increment formula (graspologic-native corrected version):
        QVI = edgeWeightToCluster - (nodeWeight × clusterWeight × adjustedResolution)
      NOTE: This differs from leidenalg. Document this deviation in godoc.
    </phase1>

    <phase2 name="refinement">
      For each Phase 1 cluster C:
        - Extract nodes in C
        - Start from singleton partition within C
        - Stochastically merge: accept move with probability proportional to exp(QVI/randomness) when QVI > 0
      Returns a NEW refined Clustering (more clusters, guaranteed well-connected).
      This phase is what differentiates Leiden from Louvain.
    </phase2>

    <phase3 name="aggregation">
      Contract refined clusters into super-nodes.
      Super-node edge weight = sum of edges between member nodes.
      Super-node self-loop = sum of internal edges.
      Returns (induced CompactNetwork, inducedClustering expressing Phase1 over super-nodes).
    </phase3>

    <outer_loop name="improveClustering">
      Run Phase1 → Phase2 → Phase3 → recurse on induced network until no improvement.
      Returns bool (any improvement occurred).
    </outer_loop>
  </algorithm>

  <implementation_notes>
    - Pass clusterWeights []float64 scratch slice into phases — allocate ONCE per improveClustering call, reuse
    - Use math/rand.Rand passed in — never use global rand
    - No heap allocation in the Phase1 inner loop
    - The weight cache (clusterWeights) must be kept consistent: update atomically when moving a node
    - Weight cache correctness is the hardest part. A stale cache silently produces wrong quality values.
      Test thoroughly with the two-community graph (two 4-cliques with bridge).
  </implementation_notes>

  <constraints>

    - No goroutines. Single-threaded.
    - go test ./... and go vet ./... must pass.
  </constraints>
